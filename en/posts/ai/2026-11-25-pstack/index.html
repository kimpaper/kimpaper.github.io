pstack — A Skill Pack for AI Coding Agents

2026 · 11 · 25 5 min read Paper

pstack is a set of skills that teaches AI coding agents how to work. poteto (Lauren Tan), who works at Cursor, published the skills they use every day. I cloned the repository (backnotprop/pstack) and read through the files. I did not install it or run it in an agent.

Version 0.15.48, as of November 24, 2026.

What it is

It is not a code library like LangChain. It is all Markdown. Each skills/<name>/SKILL.md file is one skill, and the agent reads it and follows it. It sits on top of an agent such as Claude Code, Codex or Cursor.

  • The original is the pstack folder in the cursor/plugins repository, a Cursor plugin
  • backnotprop/pstack is a mirror for other agents. It rewrites Cursor-only wording and follows upstream changes
  • MIT license
  • The author’s line is “if you want to go fast, go deep first”: the goal is less code of higher quality, not more output

What is inside

Counted on 0.15.48:

ItemCount
Skills59 (24 principles + 35 others)
poteto-mode playbooks22
Subagent definitions2 (poteto-agent, comment-sicko)
All SKILL.md files30,391 words
poteto-mode plus playbooks10,130 words

58 of the 59 skills carry disable-model-invocation: true. The agent will not pick those up on its own. You call them with /name.

Install

From the mirror’s README:

1

npx skills add backnotprop/pstack

Pick the skills and agents from the list.

For the original plugin in Claude Code:

1
2

/plugin marketplace add cursor/plugins
/plugin install pstack@cursor-plugins

Then run /pstack:setup-pstack to choose a model per role. It writes ~/.claude/rules/pstack-models.md.

I did not run either. The commands are copied from the README.

poteto-mode

The README says this is the one to use; the rest are situational. Put /poteto-mode at the start of a task and it:

  1. picks one of the 22 playbooks for the request
  2. copies that playbook’s steps into a todo list
  3. calls other skills as each step needs them

Examples from the README:

1
2
3
4
5

/poteto-mode this pr has a subtle bug where the scroll drifts every 750ms even when idle. repro
first, then fix and verify.

/poteto-mode i'm going to bed. land the stack even if ci flakes. i want everything merged by
morning.

Playbooks include bug fix, perf, feature, refactoring, prototype, babysit (drive a PR to merge-ready), shipping and autonomous run.

The bug fix playbook

A few lines from it:

1
2
3
4
5

1. Reproduce it yourself on the matching surface ...
2. Binary-search the cause. Form the candidate hypotheses, then rule them out until one survives.
3. Plan the fix. ... Delegate implementation to a subagent ...
4. Verify on the same surface. The original repro now passes.
5. Stage the commits so the failing repro lands before the fix in git history.

Reproduce first, rule out hypotheses one by one, fix, then check again on the same surface. It even asks for the failing test to be committed before the fix. One line reads “Belt-and-suspenders that ‘might help’ is a hypothesis, not a fix.” Defensive code added just in case does not ship without evidence.

Principle skills

24 files starting with principle-, one rule each. For example principle-laziness-protocol:

1
2

- Consolidate decisions. Do not repeat the same choice in several places.
- Minimize the diff. Make the smallest change that solves the problem.

Others include prove-it-works (run the real thing before calling it done), subtract-before-you-add and type-system-discipline. They read like the comments a senior engineer leaves in code review, written down for an agent.

unslop

A skill that removes AI tells from writing. The rules are numbered. A few:

1
2
3
4
5
6

7. No AI vocabulary: additionally, crucial, delve, enhance, foster, landscape, pivotal, ...
9. No "not just X, but Y". State the point.
10. Don't force ideas into threes.
13. No em dashes, en dashes, or hyphens used as dashes ...
20. No chatbot phrases ("I hope this helps!", "Let me know if...").
25. No generic conclusions. State specific plans or facts.

These are almost the same rules this blog uses to keep posts from reading as AI-written: no em dashes, no forced triples, no stock endings.

How it differs from other AI frameworks

  • LangChain and CrewAI are Python libraries for building agents. pstack gives instructions to an agent you already have, so there is no code and no dependency
  • That puts the result on the model. How well the instructions are followed depends on the model
  • The defaults are heavy. Per the README, code work goes to Opus 5.5 at xhigh effort, and the review panel is Fable 5.2, Opus 5.5 and Gemini 4 neon. It also spawns many subagents. I expect it to use a lot of tokens

Using it in Claude Code

Because the original targets Cursor, docs/harness/claude-code.md has a mapping table.

  • Cursor’s Task becomes Agent, and AskQuestion becomes AskUserQuestion
  • When one pstack skill calls another, Claude Code’s Skill tool refuses most of them, so the doc says to Read the SKILL.md file and follow it
  • Commands get a pstack: prefix: /poteto-mode is /pstack:poteto-mode
  • Steps that need Cursor-only features such as bugbot or automations are skipped with a one-line note

Codex ignores disable-model-invocation: true, so all 58 marked skills used to land in its startup prompt. The mirror fixed that by adding an agents/openai.yaml to each one (mirror issue #26).
