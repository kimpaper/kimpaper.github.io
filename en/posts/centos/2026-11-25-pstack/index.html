pstack — Seeing Where a Stuck Process Is Stuck

2026 · 11 · 25 6 min read Paper
Contents
  • What it is
  • A program that deadlocks
  • Ubuntu’s pstack package does not work
  • With gdb
  • eu-stack
  • Things to watch

Sometimes a process on a server just hangs: no CPU, no response. Before killing it, pstack shows where it is stuck.

Tested on Ubuntu 24.04 with gdb 15.1.

What it is

Give it the PID of a running process and it prints the call stack of each thread. It does not kill or restart anything.

1

pstack <pid>
  • It started as a Solaris command
  • On CentOS and RHEL it ships in the gdb package. pstack is a symlink to gstack, a script that attaches gdb and runs thread apply all bt
  • Since gdb 16, gstack is part of upstream gdb

Think of it as jstack for C and C++ programs.

A program that deadlocks

Two threads take two mutexes in opposite order. After one second they wait on each other forever.

#include <pthread.h>
#include <stdio.h>
#include <unistd.h>

pthread_mutex_t a = PTHREAD_MUTEX_INITIALIZER;
pthread_mutex_t b = PTHREAD_MUTEX_INITIALIZER;

void *worker1(void *arg) {
    pthread_mutex_lock(&a);
    sleep(1);
    pthread_mutex_lock(&b);   /* worker2 holds b */
    return NULL;
}

void *worker2(void *arg) {
    pthread_mutex_lock(&b);
    sleep(1);
    pthread_mutex_lock(&a);   /* worker1 holds a */
    return NULL;
}

int main(void) {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, worker1, NULL);
    pthread_create(&t2, NULL, worker2, NULL);
    printf("pid %d\n", getpid());
    fflush(stdout);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    return 0;
}

1
2

gcc -g -O0 -pthread -o hang hang.c
./hang &

1
2
3

$ ps -o pid,stat,nlwp,cmd -p 601
  PID STAT NLWP CMD
  601 Sl      3 ./hang

Three threads (NLWP), state S (sleeping). From the outside it looks like a normal idle process.

It is version 1.3.1, a very old tool that cannot read 64-bit processes. On Ubuntu, use gdb directly.

For each thread, read down from #0 until you hit the first frame from your own code.

  • Thread 3: worker1, hang.c:11, waiting on mutex b
  • Thread 2: worker2, hang.c:18, waiting on mutex a
  • Thread 1: main, hang.c:28, waiting in pthread_join

Thread 3 waits for b, thread 2 waits for a, and the source shows each one holds what the other wants. A deadlock.

A pstack-like wrapper

1
2
3

#!/bin/sh
# usage: mypstack <pid>
exec gdb -q -batch -ex "set pagination off" -ex "thread apply all bt" -p "$1" 2>/dev/null | grep -E '^(Thread|#)'

With gdb 16 or later you can just run gstack <pid>. Ubuntu 24.04 ships gdb 15, so it is not there.

You get function names only: no file, no line number, no mutex name. Enough to see roughly where things stopped.

Things to watch

The process pauses

While gdb is attached through ptrace, the process is stopped. Here the first run took about 1 second and later runs about 0.22 seconds. Most of that is loading symbols, so a big program takes longer. Don’t run it several times a second on a production box.

Without debug symbols

Built without -g and stripped, your own functions show up as ??.

1
2
3

#3  ___pthread_mutex_lock (mutex=0x55797918a040) at ./nptl/pthread_mutex_lock.c:93
#4  0x00005579791872fa in ?? ()
#5  0x00007f206d29cb64 in start_thread (arg=<optimized out>) at ./nptl/pthread_create.c:447

libc still has symbols, so you can tell it is waiting on a mutex, but not in which function, and the mutex names (<a>, <b>) are gone. Keep symbol files for production binaries somewhere.

Permissions

You cannot attach to another user’s process. As a normal user against a root process:

2
3
4

Could not attach to process.  If your uid matches the uid of the target
process, check the setting of /proc/sys/kernel/yama/ptrace_scope, or try
again as the root user.  For more details, see /etc/sysctl.d/10-ptrace.conf
ptrace: Inappropriate ioctl for device.

1

eu-stack: dwfl_linux_proc_report pid 601: Permission denied

If it fails even for your own process, check /proc/sys/kernel/yama/ptrace_scope. Running as root usually works.

Java and Python

pstack only sees native frames. It will not show where your own code is.

I tried a Java program that just sleeps in a loop.

    static void waitForever() throws Exception {
        while (true) Thread.sleep(10000);
    }
    public static void main(String[] args) throws Exception {
        waitForever();
    }
}
