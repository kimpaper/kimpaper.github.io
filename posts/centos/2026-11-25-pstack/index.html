pstack — 멈춘 프로세스가 어디서 멈췄는지 보기

2026 · 11 · 25 4 min read 페이퍼
목차
  • pstack 이 뭔가
  • 테스트용으로 데드락 걸리는 프로그램
  • 우분투의 pstack 패키지는 안 된다
  • gdb 로 하기
  • eu-stack
  • 주의할 것

서버에서 프로세스가 CPU 도 안 쓰고 응답도 없이 멈춰 있을때가 있다. 죽이기 전에 지금 어디서 멈춰 있는지 보는게 pstack 이다.

우분투 24.04, gdb 15.1 에서 해봤다.

pstack 이 뭔가

돌고 있는 프로세스 PID 를 주면 스레드별 콜스택을 찍어준다. 프로세스를 죽이거나 재시작하지 않는다.

1

pstack <pid>
  • 원래 솔라리스에 있던 명령이다
  • CentOS, RHEL 에서는 gdb 패키지에 들어있다. pstack 은 gstack 으로 가는 심볼릭 링크고 내부적으로는 gdb 로 붙어서 thread apply all bt 를 하는 스크립트다
  • gdb 16 부터는 gstack 이 gdb 본체에 공식으로 들어갔다

자바의 jstack 같은걸 C, C++ 프로그램에 쓴다고 보면 된다.

테스트용으로 데드락 걸리는 프로그램

#include <pthread.h>
#include <stdio.h>
#include <unistd.h>

pthread_mutex_t a = PTHREAD_MUTEX_INITIALIZER;
pthread_mutex_t b = PTHREAD_MUTEX_INITIALIZER;

void *worker1(void *arg) {
    pthread_mutex_lock(&a);
    sleep(1);
    pthread_mutex_lock(&b);   /* worker2 가 b 를 잡고 있음 */
    return NULL;
}

void *worker2(void *arg) {
    pthread_mutex_lock(&b);
    sleep(1);
    pthread_mutex_lock(&a);   /* worker1 이 a 를 잡고 있음 */
    return NULL;
}

int main(void) {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, worker1, NULL);
    pthread_create(&t2, NULL, worker2, NULL);
    printf("pid %d\n", getpid());
    fflush(stdout);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    return 0;
}

스레드 3개(NLWP), 상태는 S (잠자는 중). 겉으로 봐선 그냥 대기중인 프로세스다.

읽는 법은 각 스레드에서 #0 부터 내려가다가 내 코드가 처음 나오는 줄을 찾으면 된다.

  • Thread 3: worker1 의 hang.c:11 에서 mutex b 를 기다리는 중
  • Thread 2: worker2 의 hang.c:18 에서 mutex a 를 기다리는 중
  • Thread 1: main 의 hang.c:28 에서 pthread_join 으로 스레드 끝나길 기다리는 중

1번이 b 를 기다리고 2번이 a 를 기다린다. 소스를 보면 각자 상대가 기다리는 걸 잡고 있다. 데드락이다.

pstack 처럼 쓰기

매번 치기 귀찮아서 스크립트로 만들었다.

#!/bin/sh
# 사용법: mypstack <pid>
exec gdb -q -batch -ex "set pagination off" -ex "thread apply all bt" -p "$1" 2>/dev/null | grep -E '^(Thread|#)'

gdb 16 이상이 깔려 있으면 그냥 gstack <pid> 를 쓰면 된다. 우분투 24.04 는 gdb 15 라 없다.

주의할 것

잠깐 멈춘다

gdb 가 ptrace 로 붙는 동안 프로세스가 멈춘다. 이 테스트에서는 처음 한번 1초 정도, 그 뒤로는 0.22초 정도 걸렸다. 심볼을 읽는 시간이라 큰 프로그램이면 더 길어진다. 운영 서버에서 1초에 몇번씩 돌리고 그러면 안 된다.

디버그 심볼이 없으면

-g 없이 빌드하고 strip 까지 한 바이너리에 해보면 내 함수가 ?? 로 나온다.
