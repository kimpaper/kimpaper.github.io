pstack — AI 코딩 에이전트용 스킬 묶음

pstack 은 AI 코딩 에이전트한테 일하는 방식을 가르치는 스킬 묶음이다. Cursor 에서 일하는 poteto(Lauren Tan)가 자기가 매일 쓰는 걸 공개했다. 저장소(backnotprop/pstack)를 받아서 파일을 다 열어봤다. 설치해서 에이전트로 돌려보진 않았다.

버전은 0.15.48 (2026.11.24 기준).

pstack 이 뭔가

LangChain 같은 코드 라이브러리가 아니다. 전부 마크다운이다. skills/<이름>/SKILL.md 파일 하나가 스킬 하나고, 에이전트가 이걸 읽고 그대로 따라 일한다. Claude Code, Codex, Cursor 같은 에이전트 위에 얹어서 쓴다.

  • 원본은 cursor/plugins 저장소 안의 pstack 폴더. Cursor 플러그인이다
  • backnotprop/pstack 은 Cursor 말고 다른 에이전트에서도 쓰라고 만든 미러다. Cursor 전용 문구를 고쳐놨고, 원본이 바뀌면 따라간다
  • 라이선스는 MIT
  • 만든 사람이 내건 말은 “if you want to go fast, go deep first”. 코드를 많이 뽑는게 목표가 아니고 적게, 제대로 쓰게 하는게 목표라고 한다

뭐가 들어있나

0.15.48 기준으로 세어봤다.

항목개수
스킬59개 (원칙 24 + 나머지 35)
poteto-mode 플레이북22개
서브에이전트 정의2개 (poteto-agent, comment-sicko)
SKILL.md 전체 분량30,391 단어
poteto-mode + 플레이북 분량10,130 단어

59개 중 58개에 disable-model-invocation: true 가 붙어 있다. 이게 붙은 스킬은 에이전트가 알아서 꺼내 쓰지 않는다. 사람이 /이름 으로 불러야 동작한다.

설치

미러 README 에 나온 방법.

1

npx skills add backnotprop/pstack

목록에서 원하는 스킬이랑 에이전트를 고르면 된다.

Claude Code 에서 원본 플러그인으로 깔 때는 아래.

1
2

/plugin marketplace add cursor/plugins
/plugin install pstack@cursor-plugins

깔고 나면 /pstack:setup-pstack 으로 역할별 모델을 고른다. 설정은 ~/.claude/rules/pstack-models.md 에 저장된다.

둘 다 안해봤다. 위 명령은 README 그대로다.

poteto-mode

README 에서도 이거 하나만 쓰면 되고 나머지는 상황 따라 쓰라고 한다. 작업 시작할때 /poteto-mode 를 붙이면

  1. 요청을 보고 플레이북 22개 중 하나를 고른다
  2. 플레이북 단계를 그대로 todo 로 옮긴다
  3. 단계마다 필요한 다른 스킬을 부른다

README 에 있는 예시.

1
2
3
4
5

/poteto-mode this pr has a subtle bug where the scroll drifts every 750ms even when idle. repro
first, then fix and verify.

/poteto-mode i'm going to bed. land the stack even if ci flakes. i want everything merged by
morning.

플레이북은 bug fix, perf, feature, refactoring, prototype, babysit(PR 을 머지 가능한 상태로 만들기), shipping, autonomous run 등이 있다.

bug fix 플레이북

몇 줄 옮겨보면 이렇다.

1
2
3
4
5

1. Reproduce it yourself on the matching surface ...
2. Binary-search the cause. Form the candidate hypotheses, then rule them out until one survives.
3. Plan the fix. ... Delegate implementation to a subagent ...
4. Verify on the same surface. The original repro now passes.
5. Stage the commits so the failing repro lands before the fix in git history.

재현 먼저, 원인은 가설 세워서 하나씩 지우고, 고친 다음 같은 환경에서 다시 확인. 실패하는 테스트를 고친 코드보다 먼저 커밋하라는 것까지 있다. “Belt-and-suspenders that ‘might help’ is a hypothesis, not a fix” 라는 줄이 있다. 혹시 몰라서 넣는 방어 코드는 증거 없으면 넣지 말라는 거다.

원칙 스킬

principle- 로 시작하는 24개. 한 파일에 원칙 하나다. 예를 들면 principle-laziness-protocol.

1
2

- Consolidate decisions. Do not repeat the same choice in several places.
- Minimize the diff. Make the smallest change that solves the problem.

그 외에 prove-it-works (컴파일 된다고 끝난게 아니고 실제로 돌려서 확인), subtract-before-you-add (추가하기 전에 먼저 지워라), type-system-discipline 같은 것들이다. 사람이 코드 리뷰때 하는 잔소리를 에이전트용으로 적어둔 느낌이다.

unslop

글에서 AI 티를 빼는 스킬이다. 규칙 번호가 붙어 있다. 몇 개만.

1
2
3
4
5
6

7. No AI vocabulary: additionally, crucial, delve, enhance, foster, landscape, pivotal, ...
9. No "not just X, but Y". State the point.
10. Don't force ideas into threes.
13. No em dashes, en dashes, or hyphens used as dashes ...
20. No chatbot phrases ("I hope this helps!", "Let me know if...").
25. No generic conclusions. State specific plans or facts.

이 블로그에 AI 티 안 나게 쓰려고 정해둔 규칙이랑 거의 같다. em dash 금지, 세 개씩 짝 맞추지 말기, 뻔한 마무리 금지. 영어 글 쓸 때 그대로 가져다 쓸만하다.

다른 AI 프레임워크랑 다른 점

  • LangChain, CrewAI 같은건 파이썬 코드로 에이전트를 만드는 라이브러리다. pstack 은 이미 있는 에이전트한테 지침을 주는 거라 코드도 의존성도 없다
  • 그래서 결과가 모델한테 달려있다. 지침을 얼마나 잘 따르냐는 모델 성능 문제다
  • 기본 설정이 무겁다. README 기준으로 코드 작업은 Opus 5.5 xhigh, 리뷰 패널은 Fable 5.2 / Opus 5.5 / Gemini 4 neon 세 모델이다. 서브에이전트도 많이 띄운다. 토큰은 꽤 나갈꺼 같다

Claude Code 에서 쓸때

원본이 Cursor 용이라 docs/harness/claude-code.md 에 대응표가 따로 있다.

  • Cursor 의 Task 는 Claude Code 의 Agent, AskQuestion 은 AskUserQuestion
  • 스킬끼리 부를때 Claude Code 의 Skill 도구가 대부분의 pstack 스킬을 거부한다. 그래서 SKILL.md 파일을 Read 로 직접 읽고 따르라고 적혀 있다
  • 명령 이름 앞에 pstack: 이 붙는다. /poteto-mode 가 /pstack:poteto-mode
  • bugbot, automations 처럼 Cursor 에만 있는 기능이 필요한 단계는 한줄 남기고 건너뛴다

Codex 는 disable-model-invocation: true 를 무시해서 58개 스킬이 시작 프롬프트에 다 들어가는 문제가 있었다. 미러에서 스킬마다 agents/openai.yaml 을 넣어서 막았다 (미러 이슈 #26).
